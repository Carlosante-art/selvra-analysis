# Datasheet: personal CGM data in selvra-analysis

Following *Datasheets for Datasets* (Gebru et al., Commun ACM 2021). It describes the data the
analyses are run on. The data itself is never in this repository.

## Motivation

One person with type 1 diabetes collects his own continuous glucose data to answer
pre-registered questions about himself. The data is not collected to represent anyone else.

## Composition

- **Glucose readings**, every 5 minutes, mmol/L as shown on the receiver (mg/dL from Dexcom
  Share, converted with 18.016). Out-of-range values (Low/High) are kept at the sensor limits,
  2.2 and 22.2 mmol/L, and marked as censored.
- **Event log** (`handelser.csv`): illness, sensor change, alcohol, training, travel, stress,
  menstruation, medication change, other. Self-reported; a day without an entry means "not
  logged", not "did not happen".
- **No** insulin doses, carbohydrates, meals, sleep, heart rate or fingerstick values yet.

## Collection

- **Clarity exports** (Dexcom): local wall-clock time without a zone, include readings the
  receiver backfilled after signal loss. The authoritative history.
- **Dexcom Share via Selvra Diabetes**: polled every 5 minutes into Supabase; exact UTC instants,
  no backfill, no transmitter ID. Used only after the last Clarity reading.
- **Sensor**: Dexcom G6/G7 (generation per period is in the export's device column).
- **Time zone**: `Europe/Stockholm` (dbt var `local_timezone`). Travel across zones is not modelled.

## Preprocessing

- Readings are stored as UTC instants; daylight saving time is resolved exactly (staging model
  and unit test).
- Artefacts are flagged, never deleted: early sensor period (first 24 h), implausible jumps,
  suspected compression lows (a heuristic without ground truth).
- Every input file is identified by its SHA-256 in `raw.source_files`; every Share load is
  snapshotted. File names are not stored, because Clarity names exports after the patient.

## Uses

- Pre-registered observational analyses and randomised n-of-1 experiments on this person.
- **Not** for: conclusions about other people, diagnosis, dosing decisions, or accuracy claims
  about the sensor (there are no reference measurements).

## Distribution

- Raw data, the event log, the DuckDB files and rendered dashboards are git-ignored and never
  published. Published results are aggregates and patterns, never raw readings.
- CI runs only on synthetic data generated by `selvra_analysis.synthetic`.

## Maintenance

- Collection runs continuously through Selvra Diabetes; Clarity exports are added now and then.
- Known gaps: periods without a sensor, Share outages (visible as missing coverage), and
  unlogged events. `make rapport` shows coverage for any period.
